Project Overview

Managed the delivery of an enterprise IT management platform implementation for the Central Bank UAE — one of the most regulated and operationally sensitive ICT environments in the region. The project delivered the ManageEngine suite covering Privileged Access Management (PAM), SIEM and audit logging, patch management, and vulnerability control across the Central Bank's infrastructure environment. Budget: $800K.

Delivery was executed within the Central Bank's stringent change control framework, security governance requirements, and audit-readiness obligations. The platform was implemented to provide centralised visibility and control over IT operations, strengthen access governance, and support the Central Bank's internal and external audit programmes with reliable, retrievable evidence. All implementation activities coordinated through the Bank's IT, security, and compliance teams with formal approval gates at each phase.

My Role

Project Manager responsible for end-to-end coordination of the ManageEngine platform implementation within the Central Bank UAE's regulated ICT environment. Responsibilities included stakeholder engagement with Central Bank IT operations, security, compliance, and infrastructure administration teams; ManageEngine vendor and implementation resource coordination; phased delivery planning; change control coordination through the Bank's change advisory process; audit documentation preparation and evidence pack coordination; UAT and validation coordination; and formal handover to Central Bank IT operations team.

Delivery Approach

Phased Implementation in Regulated Environment

  • Implementation structured into phased delivery — PAM deployed first as the foundational access governance control, followed by SIEM and audit logging, then patch management and vulnerability control — each phase subject to formal acceptance before the next commenced
  • Each phase preceded by a discovery and requirements workshop with Central Bank IT and security teams — confirming scope, integration requirements, access constraints, and acceptance criteria before development or configuration commenced
  • No configuration changes applied to production infrastructure without prior approval through the Bank's change advisory process

Change Control and Approval Process

  • All infrastructure changes coordinated through Central Bank's change advisory board (CAB) — change requests prepared with full impact assessment, rollback procedures, and test evidence before submission
  • Banking change windows strictly observed — all system-impacting configuration activities scheduled for pre-approved maintenance windows outside core banking operational hours
  • Emergency change procedures documented for critical security patch deployments — approved escalation path agreed with Central Bank IT management before implementation commenced

Audit-Readiness Planning

  • Audit evidence framework established at project outset — identifying what logs, reports, access records, and configuration documentation would be required to support Central Bank internal audit and regulatory inspection requirements
  • Platform configuration designed from the start to produce audit-ready outputs — log retention periods, access report formats, and privileged session recording aligned with Central Bank audit team requirements before implementation commenced
  • Documentation package maintained throughout delivery — all configuration decisions, change approvals, test results, and sign-off artefacts retained in structured project repository accessible to Central Bank IT and compliance teams

Governance and Reporting Cadence

  • Weekly project status meetings with Central Bank IT project sponsor — covering delivery progress, phase completion status, change request pipeline, open issues, and upcoming milestone approvals
  • Formal phase completion reports submitted to Central Bank IT Director at the conclusion of each delivery phase — confirming scope delivered, acceptance testing outcomes, and readiness for next phase
  • Risk register maintained and reviewed weekly — issues with potential to affect banking operations or compliance posture escalated immediately outside the standard reporting cycle

Stakeholder & Vendor Coordination

Central Bank IT Operations

  • IT operations team as primary technical stakeholders — responsible for infrastructure access provisioning, environment readiness, integration approvals, and operational sign-off at each phase
  • IT administrators engaged in UAT and validation activities — confirming platform functionality, dashboard usability, and reporting outputs against operational requirements before acceptance

Security & Compliance Teams

  • Central Bank security team engaged throughout — reviewing PAM configuration, SIEM alert rules, access control policies, and audit log formats to confirm alignment with internal security standards
  • Compliance team consulted on audit evidence requirements — confirming log retention periods, report formats, and access record structures before platform configuration was finalised

Infrastructure Administration Teams

  • Server and network infrastructure administrators engaged for integration dependencies — confirming agent deployment scope, SNMP configuration, syslog forwarding setup, and network monitoring requirements
  • Administrators trained on PAM console operation, privileged session review, and password vault management before handover

ManageEngine Vendor Resources

  • Vendor security certifications, data residency compliance, encryption capabilities, and audit logging features verified before engagement — third-party risk assessment completed and documented
  • Vendor SLA negotiated with 4-hour response time for critical issues — supporting Central Bank's 24/7 operational requirements throughout implementation and warranty period
  • Vendor access to Central Bank systems logged, time-limited, and supervised — all vendor sessions recorded through PAM console in line with Central Bank IT security policy

Risk Management

Privileged Access Control Risk

  • Misconfiguration of PAM controls identified as highest-impact risk — mitigated through phased PAM rollout, peer review of all access policy configurations by Central Bank security team before activation, and parallel operation period validating PAM controls before legacy access methods were retired
  • Privileged session recording validated per administrator role before go-live — confirming session capture, playback quality, and audit log generation operating correctly

Audit Evidence Completeness Risk

  • Risk of audit log gaps or incomplete evidence impacting Central Bank audit readiness — mitigated through audit evidence framework defined at project outset and log completeness validation conducted before each phase acceptance
  • Log ingestion monitoring configured to alert on data source failures — ensuring Central Bank IT team was immediately notified of any gap in audit trail continuity post-deployment

SIEM and Logging Data Quality Risk

  • SIEM data quality dependent on correct log source configuration across Central Bank infrastructure — all log sources inventoried and validated during discovery phase; test ingestion conducted per source type before production SIEM activation
  • Alert rule tuning conducted with Central Bank security team post-SIEM activation — false positive rates reduced to operational levels before handover to operations team

Patch Deployment Disruption Risk

  • Automated patch deployment to banking systems identified as operationally sensitive — patch deployment policies configured with mandatory test group deployment and soak period before production rollout, with critical systems requiring manual approval before patch application
  • Patch deployment schedules aligned with Central Bank change windows — no automated production patching scheduled during core banking processing periods

Banking Change Window Constraints

  • Restricted change windows required careful scheduling of all infrastructure-impacting activities — change request pipeline managed proactively to avoid backlog and ensure sufficient lead time for CAB approval of each implementation phase activity
  • Month-end, quarter-end, and regulatory reporting periods identified as change freeze periods — implementation schedule built with awareness of these constraints from project outset

Sensitive Access and Log Handling

  • Access logs and privileged session recordings classified as sensitive — data handling procedures agreed with Central Bank security team before implementation, with access to audit evidence restricted to authorised Central Bank personnel and auditors only
  • All project documentation and configuration artefacts stored in Central Bank-approved systems — no sensitive configuration data retained on vendor or third-party systems beyond implementation engagement

Compliance & Audit Support

  • Audit evidence retrieval procedures documented and tested — Central Bank IT team confirmed ability to produce required logs and access records to defined formats before handover

Patch & Vulnerability Reporting

  • Patch compliance dashboards configured providing Central Bank IT management with real-time visibility of patch currency across infrastructure — percentage patched, outstanding patches by severity, and patch deployment history reportable on-demand
  • Vulnerability assessment reporting configured to support Central Bank IT security review cycles and regulatory inspection requirements

Internal Audit Support
